# Observed HN/C8 JBIG2 page composition

This note records the narrow, caller-table page primitive for [issue #94](https://github.com/rwv/caj2pdf-rust/issues/94), a child of [#9](https://github.com/rwv/caj2pdf-rust/issues/9). The format reference is [ITU-T T.88 (02/2000)](https://www.itu.int/rec/T-REC-T.88-200002-S/en), §§7.4.1, 7.4.8, and 8.2. Its page information body contains width, height, horizontal and vertical resolution, page flags, and striping information; §8.2 defines ordered composition of region bitmaps into the page. The original Rust implementation uses no external decoder source or normative example bytes.

## Supported profile

The [#43 external inventory](jbig2-oracle.md) measured 546 type-3 image records with five contiguous segments numbered #0–#4 and typed 48/0/0/6/38. All have page association 1 and references `[]/[]/[1]/[2]/[]`. The page flags are `0x01` and striping is zero. The immediate text and generic regions cover the full page at `(0,0)` and use the external OR operator. The parser and preflight check accept only this profile. They return typed errors for other segment layouts, unsupported page options, and region geometry or operator differences. These measurements do not characterize every valid JBIG2 page.

`read_page_info` reads the caller-delimited 19-byte page body with bounded positioned requests and checks geometry before exposing `PageInfo`. `read_generic_region_header` shares its header parser with `GenericRegionDecoder::new`; it lets the caller inspect the actual generic geometry, segment/page identity, references, and source span before constructing the final output sink. `validate_observed_page_profile` checks segment order, associations, references, the page-information span, the text body's exact segment span, and the full generic header against segment #4 before any final-page byte is emitted. The page sink compares the completed text composer's entire parsed header with preflight, including segment identity, references, placement, instance count, and operator, then starts unarmed and refuses writes. After constructing the generic decoder, the caller invokes `arm_page_output(profile.generic_header())`; this compares the decoder's re-read header with preflight and gives the sink an opaque verified-header value only on exact equality. A changed header or omitted arming poisons the operation before output. The text-region strict policy remains the default; the one raw-`0xa40c` HN/C8 case requires the explicit [#88 policy](t88-text-header-compatibility.md). Preflight carries that anomaly marker into the page report.

## Memory and output contract

The caller owns the finalized text-region random-access scratch from [#87](t88-text-composer.md). A caller may send the composer's required text-only output to a bounded counting discard sink, then release the composer and reuse its scratch. The caller grants the page operation exclusive scratch access; another handle must not change the bytes during composition. The page sink reads text bytes by position while the [generic-region decoder](jbig2-generic-template2.md) emits packed rows, ORs the two pixel values, and forwards the result to a sequential sink. Rows remain MSB-first with zero low padding bits. The final sink may apply backpressure; short writes count only bytes actually accepted. The page sink checks exact packed length and the completed generic report before it declares success. The caller must discard partial output after an error, cancellation, or a dropped pending future.

The page scratch is one packed bitmap, not a second in-memory copy. Resource budgets bound page dimensions and pixels, packed scratch/output bytes, row or chunk allocation, source/scratch/output I/O, and work. The platform supplies the scratch and final sink; the codec core does not depend on filesystem or JavaScript APIs. Exact T.88 Table E.1 MQ states remain caller supplied and external under the [#44 UNRESOLVED rights decision](t88-mq-rights.md).

## Verification boundary

Small original synthetic tests exercise page header and topology validation, OR pixels, padding, partial I/O, limits, and failure poisoning. The later SHA-pinned private [#95 full-page comparison](jbig2-page-parity.md) matched 545/545 standards-valid packed pages and the separately opted-in anomaly 1/1, with one expected strict header refusal. A clean clone still reports `NOT_RUN` with zero private-corpus cases. This primitive does not place images on HN/C8 document pages, write a PDF, implement general JBIG2 page semantics, or provide a shipped standard MQ table.
