# v0.5.0 — synchronous core, Worker APIs and more document profiles

This unstable release replaces the asynchronous Rust core and scratch bitmap
stores with synchronous ranged reads, sequential writes and per-image,
per-dictionary or per-page allocations bounded by `Limits`. Browser and Node.js
conversion runs in a Worker. The CLI retains its conversion commands and adds
explicit damaged-CAJ conversion. Update native API consumers and JavaScript
call sites together with the matching WASM build.

## Breaking changes and migration

This table describes the final v0.5.0 API. The [changelog](../../CHANGELOG.md#v050)
records individual removals, error-message changes and intermediate refactors.

| Surface / old usage | v0.5.0 migration |
| --- | --- |
| Rust asynchronous source/decoder calls, `SequentialSink` and scratch workspaces | Remove `.await`; provide `RangedSource` (or `native::SeekableSource`) and `std::io::Write`. Remove scratch resources. Keep inputs unchanged for the entire operation; HN/C8 payload SHA-256 rechecks are removed. |
| Separate format dispatch | Call the root `convert`, `inspect`, `inspect_pages`, `read_outline` or `index_pdf` facade. `ConversionOptions` is borrowed and carries format/font policy. Prefer `..ConversionOptions::default()` in literals. |
| Codec-specific budget structures | Use one `Limits`; former per-codec budget parameters are removed. `max_image_pixels` and `max_symbols` cap decoded bitmaps and dictionaries; `max_allocation_bytes` caps individual retained buffers. |
| Codec-specific error enums | Match `Error.kind` (`ErrorKind`), then use `offset`, `context` and `reason`. Removed error payloads are not available. HN/C8 I/O/cancellation now uses JS `IO`/`CANCELLED`. |
| Complete report literals or copying reports | `ConversionReport` gains `outline`, `application_info`, `images`, `omitted_pages` and `substituted_glyphs`; use `Default` where appropriate. Reports containing omissions are no longer `Copy`; borrow or clone explicitly. `DocumentInfo.page_count` is `Option<u32>`. |
| JS instance/exports and `{size, readAt}` wrappers | Pass the `WebAssembly.Module` from `loadModule()` and a browser `File`/`Blob`/OPFS handle, or a Node path/URL/descriptor/Blob. Remove `blobSource`, `fileHandleSource` and `hnc8.scratch`. Font sources use the same input types. |
| Custom raw WASM poll/resume hosts | Replace `caj2pdf_start`/`caj2pdf_io_*` with synchronous `caj2pdf_convert`/`caj2pdf_inspect` and the five host imports in the [ABI reference](../io-architecture.md#worker-model). Rust hosts use `engine::Session`/`Host`, not `Engine`/`Request`. |
| `TrueTypeFont`, whole-font embedding | Use `OpenTypeFont`, supply a face index (0 for a single face), and call `embed_font` after the last draw before `finish`. Fonts are subsetted/compressed; CFF and collection faces are supported. |
| Caller-provided QM/MQ tables | Remove CLI `--qm-states`/`--mq-states` and JS `hnc8.qmStates`/`mqStates`. Built-in standard codec states are used. Removed selected-image helpers are replaced by document conversion; see the changelog for low-level decoder removals. |
| CLI native-text input without font options | Installed fonts are discovered automatically. Use `--no-system-fonts` for the old no-search behavior, or pass explicit font paths. JS never searches installed fonts. |
| Output byte identity and early size failures | Font/content compression, font subsetting, top-first type-0 image matrices and the outline trailer `/ID` change PDF bytes. Output limits can fail during sequential writing; stage output if atomic publication is required. Do not compare old/new PDF hashes as a fidelity test. |

```js
// Before: convert(instance, blobSource(file), sink, { hnc8: { scratch } })
// v0.5.0: file is a browser File; sink is a supported sequential sink.
const module = await loadModule();
await convert(module, file, sink, { signal });
```

For prompt browser cancellation and sink backpressure use a cross-origin
isolated page (`SharedArrayBuffer`). Otherwise cancellation terminates the
Worker. Spooled inputs are now a Node path or OPFS handle. See the
[JS examples](../../js/README.md) and [native architecture](../io-architecture.md).

## Conversion improvements and remaining limits

- More measured CAJ/PDF/KDH profiles: bounded source-path metadata repair,
  absent optional link appearances, equivalent opacity resources, interrupted
  live prefixes, duplicate identical page boxes, PNG Up xrefs and Flate
  object-stream metadata. Unknown or contradictory profiles still fail.
- More measured HN-A, C8 and HN-B profiles, including generic-only JBIG2,
  empty symbol content, uncompressed images, full-page JPEG region records,
  native article records and HN-B type-3 images after text.
- `--allow-damaged` explicitly permits reported blank substitutions for eligible
  damaged CAJ pages. Exit 3 means partial output was committed. JS callers use
  `allowDamaged: true` and inspect `omittedPages`; default conversion stays strict.
- Native text needs caller/installed fonts; no fonts are bundled. Substitute
  fonts are not original-font fidelity. A measured private-use HN-B character
  may use a reported visual substitute while preserving U+E6C7 in ActualText.
- C8/HN-B bookmarks remain unverified and omitted with a warning (#303).
  Image pages receive no OCR. TEB remains unsupported. Corpus recovery and
  source-fidelity work (#406, #414, #415, #420) remains open.

## Validation and artifacts

The release workflow reruns locked native/WASM quality gates, the complete
platform inventory, actual npm tarball tests on Node and Chromium, and
artifact provenance verification. Windows/macOS binaries remain unsigned.
GitHub assets include native CLI archives, JS/WASM, OCI and SHA256SUMS;
verify them using the [provenance guide](../build-provenance.md).

The registry packages are `caj2pdf-core`, `caj2pdf-cli` (binary `caj2pdf`) and
npm `caj2pdf-rust`. `caj2pdf-wasm` remains unpublished as a Rust crate.
Initial registry publication uses owner authentication; trusted publishers
are configured after bootstrap. A GitHub release alone is not proof that a
registry upload succeeded. [Release policy](../release-policy.md) documents
this transition and the required clean-install checks.

The [conformance record](../conformance.md) separates corpus conversion,
runtime parity, glyph/image checks and selected source-render comparisons.
The 1,232 accepted originals at #408 passed native/Node/Chromium parity;
that is historical source evidence, not a fresh full-corpus run of this tag.
Optional external corpus tests for this release are NOT_RUN unless a separate
receipt records them. Filtered guest rendering tests are not compatibility
passes; their portable conversion checks and host smoke tests are separate.
The #346 source-size target remains unmet (37.9k vs 30k at its recorded
checkpoint); this release does not claim it is complete.

### Explicit damaged CAJ conversion (#297)

- CLI: opt in with `caj2pdf damaged.caj --allow-damaged -o partial.pdf`.
  Exit 3 means the PDF was committed with reported blank substitutions.
  Default strict behavior is unchanged.
- Browser and Node: pass `{ allowDamaged: true }` and inspect
  `report.omittedPages`, an array of `{ pageIndex, offset }` (zero-based
  index, absolute `bigint` input offset).
- Rust breaking change: `ConversionOptions` adds `allow_damaged`;
  `ConversionReport` adds `omitted_pages` and is no longer `Copy`.
  HN/C8 report wrappers containing it are also no longer `Copy`.
  Migrate option literals using `..ConversionOptions::default()`;
  borrow reports or explicitly clone them. No whole-file conversion API is added.
- Raw WASM: the existing start option word uses bit 0 for bookmarks and bit 1
  for damaged CAJ mode. New count/index/offset exports expose omissions.
  Use the JavaScript module with its matching WASM build.

See [partial conversion behavior](../pdf-input.md#explicit-partial-conversion-of-damaged-caj-inputs)
for remaining hard errors and shared-resource limitations. This is an unstable
feature intended for the next minor release, not a change to v0.4.0 artifacts.

### HN-B magnesium article conversion (#381)

- The measured 12-page HN-B profile now converts with all native glyphs and
  type-3 images. Additional size/symbol/metadata rules and bilevel composition
  preserve source order; unknown profiles remain errors.
- One observed private-use code retains U+E6C7. If the caller's Latin font lacks
  it, a documented visual substitute is drawn with the original code in PDF
  ActualText. The CLI warns; Rust `substituted_glyphs` and JavaScript
  `substitutedGlyphs` report the count. This does not identify its semantics.
- Rust breaking change: `ConversionReport` adds `substituted_glyphs: u64`.
  Migrate complete report literals by adding `substituted_glyphs: 0` or using
  `..ConversionReport::default()`. JavaScript reports add a `bigint` property;
  use the JS package with its matching rebuilt WASM module.
- See the [conformance checkpoint](../conformance.md#hn-b-magnesium-article-checkpoint-381)
  for selected comparisons, font limitations and NOT_RUN optional-corpus status.
  This changes unreleased builds, not existing v0.4.0 artifacts.
