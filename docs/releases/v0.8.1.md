# v0.8.1: simpler font configuration and release workflow

This unstable maintenance release preserves v0.8.0 public APIs, supported
profiles and PDF output. No migration or additional font options are needed.

```sh
cargo install --locked caj2pdf-cli --version 0.8.1
npm install caj2pdf-rust@0.8.1
caj2pdf paper.caj -o paper.pdf
```

- One authored resource manifest produces the Rust and JavaScript constants;
  CI rejects drift (#551).
- The CLI reuses core font configuration. CLI/WASM move maps and identities
  into conversion instead of cloning them; JavaScript resolves optional role
  indices once. WASM `Session` keeps its `Send + Sync` guarantees (#552).
- Default CLI/Node/browser usage comes first, advanced font flags are grouped,
  and current publication instructions are separated from linked bootstrap
  history. Coverage status now describes the unchanged 90% floor (#553).

## Validation and limits

The retained Wine-reference cohort contains 13 documents / 77 pages. Default
CLI, Node and Chromium PDFs remain byte-identical to v0.8.0. Existing custom,
absent and shared font sources, TTC faces, malformed maps, cancellation and
actual npm package tests remain covered. Seven ignored optional Rust corpus
tests are excluded from compatibility evidence. No fresh Wine pixel comparison
or additional supported profile is claimed.

Font bytes, geometry/glyph tables and embedding choices are unchanged. Native
binaries include the font pack; Node reads the packaged resource and browsers
cache it in OPFS on first use. See [bundled fonts](../bundled-fonts.md) and
[format support](../conformance.md#current-support-and-release-status). C8/HN-B
outlines and the recorded raster/unsupported-profile limitations remain.

The tagged workflow requires the complete native/container inventories,
quality and actual-package checks, and verified file/container attestations
before GitHub publication. It then publishes core/CLI to crates.io and the
same tested tarball to npm using OIDC. The tagged run and its `SHA256SUMS`
identify release bytes; Windows and macOS binaries remain unsigned. See
[build provenance](../build-provenance.md) for verification commands.
