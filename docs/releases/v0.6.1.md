# v0.6.1 — measured CAJ recovery and npm publication

## Measured CAJ tiling-pattern matrices (#414)

- Two measured CAJ originals (264 pages) now convert by making the observed
  CAJViewer/Poppler identity fallback explicit for four malformed Pattern
  matrices. All pattern streams are retained. Valid matrices and other
  malformed profiles keep their existing behavior.
- Recovery bounds the header to 512 bytes, proves the exact dictionary and
  stream boundary, and preserves source checks and sequential ranged output.
  Native, CLI and JavaScript APIs and dependencies are unchanged.
- MuPDF interprets the malformed source differently; this is a measured source
  viewer recovery, not general scientific-notation support. See the
  [conformance scope](../conformance.md#tiling-pattern-matrix-checkpoint-414).

## Upgrade and publication

There are no new public API or dependency changes since v0.6.0. npm users
upgrading from v0.5.0 must apply the [v0.6.0 migration guide](v0.6.0.md#breaking-changes-and-migration):
handle the new CAA format and nullable JavaScript page counts. Use matching
JavaScript and WASM versions.

v0.6.0 was published to GitHub and crates.io through the release workflow,
but npm interpreted its tarball path as a GitHub shorthand and the npm upload
failed before authentication. This release adds the explicit `./` local path
and uses the normal tagged OIDC pipeline for all three packages. The existing
v0.6.0 tag and assets are unchanged; no npm v0.6.0 is published by this release.
The Rust WASM crate remains unpublished.

## Validation scope

The [conformance checkpoint](../conformance.md#tiling-pattern-matrix-checkpoint-414)
records prior validation of both unchanged originals across native, Node and
Chromium, all 264 pages and 207 bookmarks, plus the broader frozen-corpus
receipt. These are attributed historical measurements, not a new full corpus
run for this version bump. Optional external-corpus checks without inputs are
NOT_RUN. Remaining unsupported inputs and fidelity limits still apply.

The tag workflow requires native/WASM quality checks, the complete platform
matrix, Node/Chromium checks of the actual npm tarball and artifact attestation
verification before registry uploads. GitHub assets include native binaries,
WASM/npm, OCI, checksums and provenance bundles. Windows/macOS binaries remain
unsigned. See [build provenance](../build-provenance.md).

```sh
cargo install --locked caj2pdf-cli --version 0.6.1
cargo add caj2pdf-core@0.6.1
npm install caj2pdf-rust@0.6.1
```
