# Bounded HN/C8 type-0 rows

This note describes [issue #55](https://github.com/rwv/caj2pdf-rust/issues/55): an original MIT row decoder for the **observed** CAJ-family type-0 image mode. It implements the independently measured [#27 row rule](jbig1-row-model.md) with the existing [T.82 arithmetic core](t82-arithmetic-core.md). Its `QmTable` is caller supplied; the exact 113 states in ITU-T T.82 (03/1993) Table 24 are **not** in the source, tests, CLI, WASM, or packages while [#30](https://github.com/rwv/caj2pdf-rust/issues/30) remains unresolved. The relevant public format sources are [ITU-T T.82](https://www.itu.int/rec/T-REC-T.82-199303-I/en) §§6.5, 6.7.1, 6.8.3 and Microsoft's [BITMAPINFOHEADER](https://learn.microsoft.com/windows/win32/api/wingdi/ns-wingdi-bitmapinfoheader) reference. The direct CAJ row-control meaning is an observed mode, not the standard cumulative LNTP rule.

## Input, row rule, and API

`Type0Decoder::new` accepts an absolute `Type0Span` over one image, a stable `RangedSource`, validated caller `QmTable`, exactly 1,024 `ContextBank` entries, forward-only `SequentialSink`, `Limits`, cancellation, `ArithmeticBudget`, and `Type0Budget`. The span includes the outer HN/C8 `record_type`; the decoder rejects values other than zero at the image start before reading its DIB. The future #28 container parser must read the actual outer type and supply it rather than assume zero. The decoder checks the entire span and the observed 48-byte 1 bpp DIB/palette wrapper before allocating rows or starting arithmetic. The accepted header has size 40, positive width/height, one plane, one bit per pixel, zero DIB compression, white-then-black palette RGB entries, `biClrUsed` 0 or 2, and `biSizeImage` 0 or the checked DIB stride times height. Palette reserved bytes, pixels-per-meter, and `biClrImportant` are not coding-mode selectors. A nonempty remainder of the image span is one delimited arithmetic SCD. Unknown wrapper values and other modes return located errors.

The decoder resets the 1,024 contexts for every image. Before each **display-order** row, one decision at context 457 means either copy the preceding row (`1`, zero background on the first row) or decode the visible pixels (`0`). Pixel contexts use ten already decoded neighbors, from most to least significant context bit: current row x−2,x−1; preceding row x−2..x+2; row before that x−1..x+1. Out-of-image neighbors are zero. The emitted DIB-stride row is MSB-first, with unused low visible bits and 32-bit DIB padding zero. `decode_next_row` emits exactly one row through the sink; `finish` requires every declared row and then flushes. The caller must discard partial sink output after any error. A dropped pending row future poisons the decoder.

`Type0Progress` reports completed rows, output bytes, and the arithmetic snapshot. The latter distinguishes logical coded bytes consumed, actual bytes fetched by bounded source reads (including prefetch), and virtual zero byte-input events after the declared SCD end. The 48-byte DIB read precedes these arithmetic counts. Errors include source offset and completed output progress. Native and browser/Node adapters can implement the same ranged-source and sequential-sink contracts; forward-only input can use the existing temporary-spool adapter.

This unstable `v0.x.y` change adds `ArithmeticSnapshot::source_bytes_fetched` to a public Rust struct. Downstream code that constructs an exhaustive `ArithmeticSnapshot` literal must supply this field; exhaustive patterns must include the field or use `..`. Code that only reads the existing fields requires no change.

`Type0Budget` caps dimensions, pixels, and neighbor work; `ArithmeticBudget` caps symbols and arithmetic work; `Limits` caps selected input, output, each I/O call, and total working allocation before the first row reserve. Three DIB-stride rows, 1,024 contexts, 113 caller table states, and the QM core's fixed 256-byte buffer bound working memory to `O(stride + contexts)`, independent of image height and source length. Each source request is at most the configured I/O chunk or 256 encoded bytes. Rows may be written in partial chunks. The decoder never loads the whole image or document into a `Vec<u8>`.

The DIB's positive height and the pinned oracle's bottom-up raw-buffer convention require a **reverse-row hash** when comparing to that oracle. This API emits display-order rows and does not reverse a page in RAM. PDF placement/orientation, HN/C8 document parsing, image composition, and JS/CLI conversion belong to #28. The standard QM core can synthesize zero bytes after a correctly declared SCD boundary, so a malformed but in-range coded span can produce plausible pixels; a successful symbol count is not an integrity check for arbitrary data.

## Verification and provenance

Original invented-table tests cover all ten context positions, widths 7/8/9 and 31/32/33, one-bit LPS output, row copy and context reset, row padding, non-type-zero outer records, partial writes, DIB errors, span and resource bounds, short/overreported reads, cancellation, sink failure, dropped futures, virtual padding, fetched-versus-consumed counts, and a 128-seed fixed-budget mutation smoke run. Expected bit traces and context positions were hand-derived, not generated by the row decoder. These synthetic tests prove API behavior, not standard-table compatibility.

The opt-in [external Rust harness](../crates/caj2pdf-core/tests/qm_caj_oracle_external.rs) now calls `Type0Decoder` for each image. Its `record_type: 0` is an assertion from the pinned #22 manifest's type-0-only catalog; the manifest stores image spans but no record-type column, so this harness does not independently parse the outer discriminator. It verifies the SHA-pinned manifest, all 27 external source identities and each selected encoded image span before decoding, then compares reverse-row raw-stride and visible-bit hashes. It uses a separately held official T.82 state fixture only at runtime, with a 16 KiB cap and SHA-256 check; documents, compressed payloads, pixels, temporary spools, state rows, and vector bytes stay outside Git. The clean-clone test is ignored and is `NOT_RUN`/zero compatibility cases, never a PASS. An explicitly requested missing or altered corpus/table fails.

From the repository root, with the external inputs supplied separately:

```sh
CAJ2PDF_CORPUS_DIR=/path/to/CAJSamples \
CAJ2PDF_T82_VECTOR_FILE=/tmp/caj26-official-vector-with-checkpoints.txt \
cargo test --release --locked -p caj2pdf-core --test qm_caj_oracle_external -- --ignored --nocapture
```

On 2026-09-25 UTC, the **new public row API** passed 1,400/1,400 pinned HN/C8 type-0 images, zero failures, and all 27 source SHA checks on the local external corpus. The final run after record-type validation took 168.25 s in release mode, with 14,964 KiB peak child RSS; its private log SHA-256 is `d8560bfcbf285a00db21bb3641253fcda20fb51fa043aa861763929cc3d92ed7`. The memory figure includes the Rust test process and excludes operating-system page cache. The result validates this caller-table row slice on the pinned corpus only. It does not grant Table 24 redistribution, build PDF pages, or establish other CAJ modes.
